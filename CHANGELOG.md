## [0.1.2] - 2026-10-19

### 简体中文

**新增**
- 通过 Cloudflare Access 验证 Web 用户，并为每个用户建立独立个人工作区；任务、汇报、Overview 和 Agent 密钥按工作区隔离。
- 在设置中创建、查看元数据并撤销个人 Agent 密钥；密钥明文仅在创建时显示一次，可设置到期时间。
- 将 Web API 与远程 MCP 分到不同 Worker hostname；MCP 仅在专用主机的 `/mcp` 路径接受个人 Agent 密钥。
- 新增历史页面，支持保留完整任务快照、查看归档任务的全部工作汇报，并按类型、来源和任务筛选活动记录。
- 记录任务创建、更新、状态变化、归档和工作汇报活动；Overview 显示最近活动，并允许删除单条活动或清理整组历史。报告与活动保留已验证操作者的 ID 关联；`actor_name` 读取时解析为当前邮箱或 Agent Key 名称，改名会改变旧记录的显示名称。

**改进**
- 将真实任务或汇报变更与活动记录放在同一数据库事务中；无实际值变化的任务更新不改更新时间，也不生成活动。
- Agent 密钥支持编辑名称和到期时间；列表只回显 `tlu_` 后的 3 个字符，撤销后保留记录和状态。

**修复**
- 将 Agent Key 工作区外键的 ORM 约束名与既有 PostgreSQL 迁移生成的约束名对齐；该元数据修正不需要新增数据库迁移或改动数据。

**升级说明**
- 将既有数据库按顺序升级：应用 `0002_identity_workspace`，由目标用户通过 Access 登录建立工作区；若旧共享工作区仍有未归属任务，维护者须在运行 `0003_task_workspace_required` 时提供该用户的 Access issuer、subject、已验证邮箱及确认值 `assign-existing-tasks`。迁移会将任务和汇报归入该工作区，不推断或拆分归属；旧汇报无法恢复的用户及密钥归属保持为空。最后应用 `0004_task_history`。迁移不会随 API 启动自动执行。
- `0004_task_history` 会将已有任务保留为当前任务，不补造历史活动。
- `DELETE /api/tasks/{id}` 省略 `history` 时仍沿用原有永久删除行为；新版 Web 界面会明确询问是否保留历史。

### English

**Added**
- Authenticate Web users through Cloudflare Access and create an isolated personal workspace for each user; tasks, reports, Overview data, and Agent keys are scoped to that workspace.
- Create, inspect metadata for, and revoke personal Agent keys in Settings; plaintext is displayed only at creation, with optional expiry.
- Split the Web API and remote MCP across separate Worker hostnames; personal Agent keys are accepted for MCP only at `/mcp` on its dedicated host.
- Added a History page for preserving complete task snapshots, reading all archived reports, and filtering activity by type, source, and task.
- Recorded task creation, updates, status changes, archiving, and report creation; Overview shows recent activity, and users can delete one activity or clear a task's history group. Reports and activities retain verified actor ID associations; `actor_name` resolves to the current email or Agent key name when read, so renames change the displayed name on older records.

**Improved**
- Commit each real task or report change with its activity record in one database transaction; no-op task updates neither change the timestamp nor create activity.
- Agent keys can be edited and revoked; lists expose only three key characters after `tlu_` and retain revoked records with their status.

**Fixed**
- Aligned the ORM foreign key name for Agent-key workspaces with the constraint name generated by the existing PostgreSQL migration; this metadata correction requires no schema migration or data change.

**Upgrade notes**
- Upgrade an existing database in order: apply `0002_identity_workspace` and have the intended owner sign in through Access to create a workspace. If unassigned tasks remain in the former shared workspace, the maintainer must provide that user's Access issuer, subject, verified email, and the confirmation value `assign-existing-tasks` when applying `0003_task_workspace_required`. The migration assigns the tasks and reports to that workspace without inferring or splitting ownership; unrecoverable user and key attribution on legacy reports remains unset. Then apply `0004_task_history`. Migrations do not run automatically at API startup.
- `0004_task_history` leaves existing tasks current and does not fabricate historical activity.
- Omitting `history` from `DELETE /api/tasks/{id}` retains the previous permanent-deletion behavior; the updated Web interface asks users to choose whether to preserve history.

## [0.1.1] - 2026-10-18

### 简体中文

**新增**
- 新增响应式工作台，包括 Overview 统计、任务列表和详情；支持任务搜索、状态筛选、排序、分页以及 URL 保留筛选条件。
- 任务与汇报 API 支持稳定分页、筛选和全工作区统计；MCP 新增 `list_reports` 工具。
- 为 PostgreSQL 引入 Alembic 版本化迁移基线及 PostgreSQL 17 集成测试。

**改进**
- API 与 Worker 支持跨层 Request ID；增加请求日志、受保护的数据库就绪检查与数据库连接超时。
- 为 REST 和 MCP 分别设置请求体大小限制（64 KiB 与 1 MiB），并统一异常响应的安全响应头。

**升级说明**
- 已有 PostgreSQL 数据库需要先核对结构，再由维护者登记 Alembic 基线；应用启动时不会自动运行迁移。
- 当前使用单一共享工作区，Web 和 Agent 令牌都具备全工作区任务访问权限。

### English

**Added**
- Added a responsive console with Overview, task list and detail views, search, status filters, sorting, pagination, and URL-persisted filters.
- Added stable task/report pagination and filtering, workspace-wide totals, and the MCP `list_reports` tool.
- Added an Alembic migration baseline and PostgreSQL 17 integration tests.

**Improved**
- Added cross-layer request IDs, request logging, protected database readiness checks, and database connection timeouts.
- Applied separate REST (64 KiB) and MCP (1 MiB) request body limits and consistent security headers on unexpected errors.

**Upgrade notes**
- Existing PostgreSQL databases require schema verification before an operator records the Alembic baseline; migrations do not run automatically on application startup.
- The product uses one shared workspace; Web and Agent tokens can access every task in that workspace.

## [0.1.0] - 2026-10-15

### 简体中文

首个公开版本。

**新增**
- 提供 React 任务管理界面，支持创建、查询、编辑、删除、状态筛选及用户与 Agent 的进度汇报。
- Cloudflare Worker 提供静态资源与 `/api/*`、`/mcp` 公网入口；FastAPI 与 PostgreSQL 负责业务和持久化。
- MCP 提供本地 stdio 和远程 Streamable HTTP 传输，支持任务读取、创建、更新与报告提交。
- 提供 Docker Compose、Caddy、Cloudflare Tunnel 部署配置以及独立 Web/Agent 令牌和网关密钥。

**改进**
- 改善任务编辑、汇报来源归属、错误提示、表单可访问性和连接状态显示。
- Worker 保护回源密钥绑定并强制安全的 HTTP 处理；增加生产 PostgreSQL 逻辑备份和隔离恢复工具。

**使用限制**
- 单一共享工作区；尚不提供独立用户账户、精细权限或 MCP OAuth。
- 远程 MCP 使用无状态 HTTP 传输；数据库迁移由维护者操作。

### English

Initial public release.

**Added**
- Added a React task interface with CRUD, status filters, and human/Agent progress reports.
- Cloudflare Worker serves static assets and public `/api/*` and `/mcp` ingress; FastAPI and PostgreSQL own business logic and persistence.
- Added local stdio and remote Streamable HTTP MCP transports for task reads, creation, updates, and reporting.
- Added Docker Compose, Caddy, Cloudflare Tunnel, separate Web/Agent tokens, and a gateway secret.

**Improved**
- Improved task editing, server-verified report attribution, error handling, form accessibility, and connection status.
- Hardened Worker origin binding preservation and HTTP handling, with PostgreSQL logical backup and isolated restore tools.

**Limitations**
- One shared workspace, without individual user accounts, fine-grained authorization, or MCP OAuth.
- Remote MCP uses stateless HTTP transport; database migrations require an operator.
